# 변수 동작 명세

defE2End 변수의 범위·실행 때 값 결정·권한·화면 동작 명세다. 데이터 모델·API·담당 경계는 [variables-contract.md](variables-contract.md) 가 기준이고, 스텝 안에서의 치환 규칙은 [action-spec.md](action-spec.md) 2.6절이 기준이다.

요약: 변수는 **환경**에 정의하고, 변수마다 범위를 정한다.
- **공유 변수**(`shared`): 환경에 값 하나. 그 환경으로 도는 모든 실행이 같은 값을 쓴다.
- **개인 변수**(`personal`): 환경에는 정의만 두고, 값은 사람마다 따로 넣는다. 실행은 **요청자 본인 값만** 쓴다. 사람 요청자가 없는 실행(스케줄·봇 토큰)은 그 스케줄·토큰에 넣은 값을 쓴다.

---

## 1. 범위·키

### 1.1 변수 정의
- 한 변수 = (환경, 이름). 이름은 환경 안에서 유일하다. 한 사이트의 환경(예: 개발·운영)마다 따로 정의하고 값을 넣는다.
- 변수마다 **범위**(`shared`·`personal`)와 **비밀 표시**(`isSecret`)를 둔다.
- 환경이 지워지면 그 변수와 값도 지워진다.

### 1.2 개인 값
- 한 값 = (변수, 사용자). 사용자가 지워지면 그 사람의 개인 값도 지워진다.
- 스케줄 값·봇 값: 스케줄은 대상 환경의 개인 변수마다, 봇 토큰은 개인 변수마다 따로 값을 둔다. 스케줄의 환경을 바꾸면 스케줄 값은 확인 뒤 지워진다.

### 1.3 시나리오에서 변수 쓰기
- 스텝의 `url`·`selector`·`value`·`expected` 에서 `{{이름}}` 을 찾는다. 이름은 ASCII 영문자·숫자·밑줄 한 글자 이상이고, 대소문자를 구분한다. 한글·하이픈·점·공백이 든 이름은 변수가 아니며 글자 그대로 남는다. 세부는 action-spec 2.6.

### 1.4 범위·비밀 표시 바꾸기
- 범위를 바꾸면: 공유 → 개인은 공유 값을 지우고, 개인 → 공유는 모든 개인 값을 지운다. 화면은 바꾸기 전에 확인을 받는다.
- 비밀 표시를 바꾸면: 개인 변수는 모든 개인 값을 지운다. 공유 변수는 평문 → 비밀이면 값을 암호화해 남기고, 비밀 → 평문이면 새 값을 요구한다. 평문과 암호문이 섞이지 않는다.

---

## 2. 실행 때 값 결정

### 2.1 공통 규칙
1. 실행할 스텝에서 `{{이름}}` 목록을 뽑는다.
2. 공유 변수는 환경의 값, 개인 변수는 **실행 요청자**의 값을 쓴다. 시나리오 작성자나 다른 사람의 값은 쓰지 않는다.
3. **폴백 없음**: 개인 값이 없으면 공유 값·다른 사람 값·다른 환경 값으로 넘어가지 않는다.
4. 변수로 정의되지 않은 `{{이름}}` 은 글자 그대로 남는다(실패 아님). 값이 빈 공유 비밀 변수를 쓰는 스텝은 `failed`(`missing_secret`)다(action-spec 2.6).
5. 해석한 값은 메모리에만 두고, 비밀 값은 결과·로그·스크린샷에서 가린다. 실행 결과에는 쓰인 변수의 이름과 범위만 남길 수 있고 값은 남기지 않는다.

### 2.2 경로별
| 경로 | 개인 변수의 값 | 값이 없을 때 |
|---|---|---|
| 단건·그룹·재실행·시험 실행(웹·MCP, 서버·PC 공통) | 요청자 본인 값 | 생성 때 **409 `variable_missing { keys }`** |
| 스케줄 | 스케줄에 넣은 값 | 발화를 `refused(variable_missing)` 로 기록하고 알림 |
| 봇 토큰(`/api/v1`) | 토큰에 넣은 값 | 409 `variable_missing` |
| PC 실행 | 서버가 위 규칙으로 해석한 값을 `run` 메시지에 실어 그 실행의 기기로만 보낸다. 앱은 메모리에만 두고 디스크·로그에 남기지 않는다 | 서버 쪽 규칙과 같음 |

- 검사는 실행 생성 때 한 번(모든 경로가 같은 생성 함수를 쓴다), 해석은 실행 시작 때 한 번 한다. 생성 뒤 값이 지워져 시작 때 없으면 그 실행은 `error`(`variable_missing`)로 끝난다.

### 2.3 웹 실행 화면
- 실행·시험 실행 대화상자가 `variable_missing` 을 받으면 빠진 이름 목록과 "내 값 넣기"로 가는 길을 보여 준다. 실행 화면에서 값을 받아 대신 저장하지는 않는다.

---

## 3. 보기·쓰기 권한

- 변수 정의(만들기·범위·비밀 표시·이름·삭제)와 공유 값 쓰기: `config.write`(EDITOR 이상).
- 개인 값 쓰기·지우기: `variable.personal.write`(EDITOR 이상, **본인 값만**). 읽기도 본인 값만.
- 남의 개인 값은 어떤 API·화면·내보내기·로그에도 나오지 않는다. 다른 사람이 값을 넣었는지 여부도 보이지 않는다(관리자 포함).
- 비밀 값은 **쓰기 전용**이다: 암호화 저장되고, 저장 뒤에는 `hasValue` 만 보인다. 바꾸려면 새 값을 쓴다. 비밀이 아닌 값은 볼 수 있다(개인 값은 본인만).
- 스케줄 값은 `schedule.write`(EDITOR 이상), 봇 값은 `botToken.write`(ADMIN)가 고친다. 비밀 값은 아무도 다시 볼 수 없고, 바꾼 사람·시각은 값 없이 감사 기록에 남는다.

---

## 4. 화면

- 환경의 변수 표에 "범위" 열(공유/개인)이 있다. 개인 변수 행의 값 칸은 **"내 값"** 이고, 비어 있으면 "내 값이 없어요 — 이 변수를 쓰는 실행은 막혀요" 안내를 보인다.
- 스케줄·봇 토큰 화면에서 개인 변수마다 그 스케줄·토큰의 값을 넣는다.
- **내보내기·가져오기**: 변수 정의(이름·범위·비밀 표시)만 옮긴다. 공유 비밀 값과 모든 개인 값은 빠진다. 가져온 비밀 공유 변수는 "값 필요" 상태가 되고, 개인 변수는 각자 값을 채운다.

---

## 5. 로그인 세션과의 관계

- 변수와 로그인 세션은 별도 저장소이고 실행 때 서로를 참조하지 않는다.
- 같은 원칙을 쓴다: 키 범위는 **환경 단위**, 사람의 실행은 **요청자 본인 것만**, 없으면 **명시 오류**(세션은 `auth_session_missing`), 다른 사람 것으로 넘어가지 않는다. 스케줄·봇 토큰은 각자 따로 둔 값과 세션을 쓴다.
- 로그인 세션을 만드는 시나리오가 `{{ID}}`·`{{PASSWORD}}` 같은 개인 변수를 쓰면, 그 세션은 요청자의 값으로 로그인해 요청자의 세션으로 저장된다.

---

## 6. 사용자가 알아야 할 규칙·한계

1. 개인 변수를 참조하는 시나리오는 실행하는 사람마다 자기 값을 넣어야 돈다. 공유 값으로 대신하지 않는다.
2. 같은 사이트라도 환경마다 값을 따로 넣는다.
3. 범위나 비밀 표시를 바꾸면 1.4 대로 값이 지워진다.
4. 비밀 값은 넣은 사람도 다시 볼 수 없다.
5. 스텝은 편집 권한이 있는 누구나 고칠 수 있고, 스케줄·봇은 그 스텝을 자기 값으로 돌린다. 스텝을 고쳐 값을 빼내는 것은 같은 조직 안의 신뢰로 다루며, defE2End 가 막는다고 약속하지 않는다.
