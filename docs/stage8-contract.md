# 단계 8 계약 — 1.0 배포

> 2026-10-16. 단계 8(문서·이미지와 앱 배포·공개 전 점검)을 여러 사람이 나눠 만들 때 맞춰야 하는 결정. 바꾸려면 이 문서부터 고친다.
> 상위 문서: [plan.md](plan.md) 1절(앱 배포·책임 경계)·6절(업그레이드·백업·버전)·8절·9절(공개 전 점검).

## 0. 완료 기준 (plan 8절)

- **신규 설치**: 빈 PC 에서 문서대로 `docker compose` 로 서버를 띄우고 첫 관리자를 만들 수 있다.
- **업그레이드**: 이전 버전 이미지로 데이터를 만든 뒤 새 버전으로 올려도 데이터가 남고 동작한다(CI 시험).
- **백업·복원**: 백업 명령으로 만든 묶음을 빈 환경에 복원하면 같은 데이터가 보인다(CI 시험, 릴리스마다).
- **실제 다운로드 파일 설치**: GitHub Releases 에서 받은 mac·Windows 설치 파일을 깨끗한 PC 에 설치해 실행하고 서버에 연결한다(사람이 하는 시험, 체크섬 확인 포함).

## 1. 결정

| 항목 | 결정 |
|---|---|
| 버전 | 저장소 하나에 버전 하나(semver). 첫 정식은 `1.0.0`, 그 전 시험 릴리스는 `1.0.0-rc.N`. 버전의 출처는 git 태그 `vX.Y.Z` — 릴리스 빌드가 태그에서 읽어 앱·서버·runner·MCP 에 새긴다 |
| 서버 이미지 | `ghcr.io/97kim/defe2end-web`, `-worker`, `-migrate`. linux/amd64·arm64. 태그는 `X.Y.Z` 와 `X.Y` 만 — `latest` 는 두지 않는다(버전 고정, plan 6절) |
| compose | `deploy/docker-compose.yml` 은 이미지 기반(`DEFE2END_VERSION` 환경 변수로 버전 고정). 소스에서 빌드하는 구성은 `deploy/docker-compose.build.yml` 로 옮긴다(개발·CI 용) |
| 앱 | mac(dmg, arm64·x64 각각), Windows(nsis, x64). **서명 없음**. 자동 업데이트 없음 |
| 새 버전 알림 | 앱이 시작할 때와 하루 한 번 GitHub Releases 의 최신 정식 릴리스를 확인해, 더 새 버전이면 알림(다운로드 페이지 링크). 설정에서 끌 수 있다. 시험 릴리스(`-rc`)는 알리지 않는다. 네트워크 실패는 조용히 넘긴다 |
| 릴리스 작업 | `v*` 태그 push 로 GitHub Actions 가 돈다: 전체 시험 → 이미지 빌드·게시 → 앱 빌드 → SBOM·제3자 고지·체크섬 → **초안(draft) 릴리스** 생성. 게시는 사람이 확인하고 누른다 |
| SBOM·고지 | 배포물마다 CycloneDX SBOM 과 제3자 고지(Playwright·Electron·Chromium 포함). 이미지는 `/licenses/` 에, 앱은 리소스 폴더에, 릴리스 자산으로도 올린다 |
| 체크섬 | 릴리스 자산 전체의 `SHA256SUMS` |
| 백업 | migrate 이미지에 `backup`·`restore` 명령. 대상: DB(일관된 시점의 덤프) + 파일 저장소 + 설정 확인 목록. **암호화 키는 묶음에 넣지 않는다**(따로 보관하라고 안내, 키 없이 복원하면 비밀 값은 읽을 수 없음을 명시) |
| 업그레이드 시험 | CI 에서 이전 정식 릴리스 이미지(없으면 기준 커밋의 마이그레이션)로 데이터를 만든 뒤 지금 버전으로 올리고 확인 |
| 문서 | `docs/guide/`(영어)와 `docs/guide/ko/`(한국어). 설치·설정·업그레이드·백업과 복원·데스크톱 앱·AI 연결·보안과 한계·최소 사양·문제 해결. README 에 빠른 시작 |
| 최소 사양 | 측정 전 값은 "추정"으로 표시(plan 6절) |

## 2. 문서 (`docs/guide` — 문서 담당)

- **설치**: 필요한 것(Docker·Compose 버전), `.env` 만들기(키 생성 명령 포함), `docker compose up -d`, 첫 관리자, HTTPS 는 사용자 몫(리버스 프록시 예시는 짧게, 특정 클라우드 이름 없이).
- **설정**: 모든 환경 변수 표(이름·필수 여부·기본값·설명). 코드에서 실제로 읽는 변수와 일치해야 한다(문서 담당이 코드에서 목록을 뽑아 대조).
- **업그레이드**: 버전 바꾸기, 업그레이드 전 백업, 건너뛰기 경로는 릴리스 노트에서 확인.
- **백업과 복원**: 4절 명령 사용법, 키 따로 보관, 빈 환경 복원 순서.
- **데스크톱 앱**: 다운로드·체크섬 확인·설치. 서명이 없어 처음 실행 때 OS 가 막는 경우의 정상적인 열기 방법(mac 의 "시스템 설정 > 개인정보 보호 및 보안 > 그래도 열기", Windows SmartScreen 의 "추가 정보 > 실행")만 안내하고, 보안 기능 전체를 끄라고 안내하지 않는다. 회사 정책으로 막히는 환경이 있음을 밝힌다. 서버 연결, 새 버전 알림 끄기.
- **AI 연결**: 지원하는 CLI 와 확인한 버전, 앱 채팅이 defE2End 도구만 쓰는 이유와 한계, 모델 요청은 외부로 나간다는 점, MCP 등록.
- **보안과 한계**: 비밀 값 암호화와 키, 마스킹이 가리지 못하는 것(`docs/masking.md` 연결), 같은 OS 사용자 프로세스에 대한 한계, Windows 파이프 권한 상태.
- **문체**: 영어는 짧고 직접적으로, 한국어는 조사를 붙여 쓰고 해라체로 끝내지 않는다. 특정 회사·서비스 이름을 쓰지 않는다(공개 연습용 사이트 예시는 괜찮다).

## 3. 릴리스 파이프라인 (`.github/workflows/release.yml` 등 — 배포 담당)

- 태그에서 버전을 읽어 각 패키지에 새기는 스크립트(빌드 산출물에만, 커밋하지 않음). 앱의 `app.getVersion()`, 서버의 버전 응답, runner·MCP 버전이 같은 값.
- 이미지: buildx 다중 아키텍처, GHCR 게시(`GITHUB_TOKEN` 의 `packages: write` — 이 작업에만 권한), 이미지 라벨(OCI source·version·revision), `/licenses/` 에 SBOM·고지.
- 앱: mac arm64·x64 dmg, Windows x64 nsis. 리소스에 SBOM·고지. 서명 관련 환경 변수는 비워 둔다.
- SBOM 은 CycloneDX(도구는 판단 — 오프라인 재현 가능하고 라이선스가 자유로운 것). 제3자 고지는 SBOM 에서 라이선스 본문을 모아 만든다.
- `SHA256SUMS`, 초안 릴리스(자산 전부, 릴리스 노트 초안). 태그가 `-rc` 면 시험 릴리스(prerelease)로.
- 기존 `ci.yml` 은 그대로 두되, 수동 실행의 설치 파일 업로드는 유지.
- 새 버전 알림(1절)을 앱에 구현한다(설정 저장·끄기, 정식만, 실패 조용히, 시험).
- 공개 점검: 릴리스 산출물(이미지 파일 목록·앱 리소스)에 클린룸 검사를 돌리는 단계를 넣는다(CI 비밀 값 `CLEANROOM_HASHES`).

## 4. 백업·복원·업그레이드 (`packages/db` 또는 migrate 이미지 — 운영 담당)

- `backup <디렉터리>`: DB 를 일관된 시점으로 덤프(`pg_dump` 사용자 정의 형식, 같은 트랜잭션 스냅샷), 파일 저장소를 묶고, 버전·마이그레이션 상태·필요한 환경 변수 이름 목록(값 없이)을 담은 `manifest.json`. 키는 넣지 않는다.
- `restore <디렉터리>`: 빈 DB·빈 저장소에만(비어 있지 않으면 거부, 강제 옵션 없음), 버전이 다르면 거부하고 안내(같은 버전으로 복원 뒤 업그레이드).
- 실행 중 백업: worker·web 이 돌아도 DB 덤프는 일관되게, 파일은 DB 덤프 뒤에 묶어 덤프가 가리키는 파일이 빠지지 않게(덤프 이후에 생긴 파일은 남아도 됨 — 고아 정리가 지운다).
- **CI 시험**: compose 로 띄워 데이터(사용자·시나리오·실행·산출물·비밀 변수)를 만들고 → 백업 → 빈 환경에 복원(같은 키) → 데이터·파일·비밀 값 확인. 키 없이 복원하면 비밀 값이 읽히지 않고 안내가 나오는지도.
- **업그레이드 시험**: 이전 정식 릴리스 이미지가 있으면 그걸로, 없으면 기준 커밋(첫 공개 커밋)의 마이그레이션으로 DB 를 만들고 데이터를 넣은 뒤 지금 버전으로 migrate → 앱 확인.

## 5. 사람이 하는 시험 (리드·사용자)

- 깨끗한 mac 에서 실제 다운로드 파일 설치·실행·연결·실행 한 번, 수동 업데이트(새 버전 설치) 한 번.
- 깨끗한 Windows PC 에서 같은 시험 + Windows 파이프 권한 확인(단계 6 에서 미룬 것). **Windows PC 가 필요하다.**
- 게시: 초안 릴리스 확인 → 게시(사용자에게 묻고).

## 6. 진행 순서

2. **3갈래 병렬**(각 25분 상한): 문서 담당(2절), 배포 담당(3절), 운영 담당(4절).
