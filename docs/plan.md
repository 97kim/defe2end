# defE2End — 계획

> 2026-10-10 작성, 같은 날 리뷰 반영. 회사·개인이 자기 서버에 설치해 쓰는 오픈 소스 E2E 테스트 플랫폼을 처음부터 새로 만든다.
> 이 문서는 저장소에 들어가 1.0 에서 공개된다. 특정 회사·서비스 이름이나 내부 사정은 쓰지 않는다.

### 1.1 책임 경계

| 우리가 제공 | 사용자 몫 |
|---|---|
| 소스 코드, 컨테이너 이미지(web·worker·migrate), 예시 `docker-compose.yml` | 서버·클라우드 선택과 배포(AWS·GCP·Azure·사내 서버 등) |
| 설정값(환경 변수) 문서, 최소 사양 | 도메인·HTTPS 인증서·리버스 프록시 |
| 업그레이드·백업·복원 **방법** 안내와 이를 돕는 명령(`defe2end admin …`) | 실제 백업 실행·보관, 업그레이드 시점 결정 |
| 데스크톱 앱 설치 파일(GitHub Releases) | DB 운영(관리형 DB 또는 컨테이너), 모니터링, 보안 패치 적용 |

- 클라우드 전용 배포 스크립트(Terraform·Helm 등)는 1.0 에서 만들지 않는다. 표준 컨테이너·환경 변수만 지키면 어디서든 뜨게 한다.
- 관리형 Postgres(RDS·Cloud SQL·Azure Database)와 S3 호환 저장소를 그대로 붙일 수 있게 설정만 열어 둔다.

| 액션 | 기본(이동·클릭·입력·선택·대기·스크롤·스크린샷·검증) + 고급(iframe·팝업·dialog·파일 업로드·API 응답 검증·DOM 검증·스텝 재시도). 1.0 액션 목록과 판정 의미는 단계 3 에서 표로 확정 |

| 자동화 | 스케줄(cron, 시간대 지정), Slack 알림·일일 리포트·테스트 전송, 봇 토큰 + `/api/v1`(CI 용) |

| 계정 | 로그인(이메일·OIDC·GitHub), 워크스페이스·역할·초대 |

### 2.2 1.0 지원 조합(좁혀서 깊게)

기능은 줄이지 않고, **지원하는 조합을 좁힌다.** 마스킹·권한·복구는 줄이는 대상이 아니다.

- 브라우저: **Chromium** 만
- worker: **1개 인스턴스 기준**으로 시험(여러 개는 동작하게 만들되 1.0 지원 대상은 아님)
- 앱: mac(Apple Silicon·Intel), Windows x64
- AI CLI: Claude Code·Codex 의 **확인한 버전 범위**만(문서에 명시)
- 녹화: 명시한 액션만 기록

### 2.3 CI 용 API (`/api/v1`)

봇 토큰 전용, 응답 형식 고정.

- `POST /runs` 실행 생성(시나리오 또는 그룹, 환경, **중복 방지 키**) · `GET /runs/{id}` 조회 · `POST /runs/{id}/cancel`
- 종료 상태를 구분한다: `passed` / `failed`(검증 실패) / `error`(인프라·실행 오류) / `cancelled` / `timed_out`. **CI 는 `passed` 만 통과로 본다.**
- 봇 토큰: 워크스페이스 고정, 권한 범위, 만료일, 폐기, 마지막 사용 시각. 토큰 원문은 만들 때 한 번만 보여 주고 해시만 저장

## 3. 구조

```
defe2end/                 pnpm workspace + Turborepo
  apps/
    web/                   Next.js — 화면·API·데스크톱 앱 SSE 연결
    worker/                큐 소비(서버 실행), 스케줄러, 비교 확정, 보존 정리
    desktop/               Electron — PC 실행, 사이드 브라우저, AI 채팅, 녹화, 소켓 서버
    mcp/                   defe2end-mcp (stdio) — 서버 API + 데스크톱 소켓 호출
  packages/
    runner/                스텝 실행 엔진 — worker·desktop 공용
    db/                    Prisma 스키마·마이그레이션
    shared/                타입, API·프로토콜 계약, 권한 규칙, 판정 규칙
    i18n/                  영어·한국어 문구
  deploy/docker-compose.yml
```

- 기술: TypeScript, Next.js, Prisma + Postgres, Playwright, Electron + electron-builder, Better Auth(2026-10-11 Auth.js 에서 변경 — Next.js 용 v5 가 아직 베타), next-intl, vitest, GitHub Actions, GHCR.
- **시작 순서**: postgres 준비 → `migrate` 일회성 컨테이너 성공 → web·worker 시작(compose `depends_on: service_completed_successfully`). 마이그레이션이 실패하면 web·worker 가 뜨지 않는다.
- **스케줄러는 worker 한 곳에서만.** 여러 worker 가 떠도 DB 잠금으로 한 곳만 스케줄을 돌린다.
- 데스크톱 앱은 첫 실행 때 서버 주소를 받는다(HTTPS 기본, `http` 는 `localhost` 만 허용). 화면은 서버의 웹 UI, 사이드 브라우저는 별도 뷰.
- **판정 규칙은 서버·화면이 같은 함수**(shared)를 쓴다.

## 4. 보안 설계

### 4.1 권한
- 모든 진입점(API·SSE·파일 다운로드·MCP·봇 토큰)이 `can(actor, action, resource)` 한 함수를 거친다. 기능별로 따로 검사하지 않는다.
- 워크스페이스를 넘는 접근, 역할 변경·탈퇴 후 접근 거부를 시험으로 보장한다.

### 4.2 로컬 MCP(stdio)
- 포트를 열지 않는다. 클라이언트(Claude Code·Codex)가 프로세스를 띄운다.
- 서버 호출에 쓰는 자격 증명은 **OS 보안 저장소**(macOS 키체인·Windows 자격 증명 관리자)에서 읽는다. 데스크톱 앱 로그아웃·서버 변경 시 폐기.
- 데스크톱 소켓: 같은 OS 사용자만 접근(유닉스 소켓 권한 0600·Windows named pipe ACL), 요청마다 앱이 발급한 세션 토큰 확인.
- 도구는 사용자 역할 범위 안에서만. 파괴적 작업(실행 취소·전체 중지·삭제)은 MCP 에 두지 않고 웹·앱에서 사람이 한다(AI 가 확인 단계를 스스로 통과할 수 있어서).
- 같은 OS 사용자 권한을 이미 가진 악성 프로세스까지 막는다고 약속하지 않는다(문서에 명시).

### 4.3 Electron 격리
- 원격 콘텐츠(서버 웹 UI·테스트 대상 페이지)에 Node 접근 없음: `contextIsolation`·`sandbox` 켬, `nodeIntegration` 끔.
- 서버 웹 UI 와 테스트 브라우저는 **세션·저장소 분리.**
- IPC 는 최소 목록만, 보낸 프레임의 출처를 확인. 파일 선택·다운로드·외부 URL 열기·CLI 실행은 각각 허용 목록.
- 서버 주소가 바뀌면 이전 자격 증명을 보내지 않는다.

### 4.4 실행 범위(runner)
- 한 조직 안의 신뢰를 전제로 하되, 서버 실행은 **클라우드 메타데이터 주소(169.254.169.254 등) 기본 차단**, 내부망 대역 차단은 설정으로 켤 수 있게.
- 파일 업로드 액션은 워크스페이스 첨부 파일만(서버 파일 경로 접근 불가).
- 실행마다 새 브라우저 컨텍스트, worker 는 비루트·Chromium 샌드박스.

### 4.5 비밀 값과 마스킹
- 변수의 비밀 값·Slack 웹훅·테스트 대상 로그인 세션은 **암호화 저장.** 키는 설치 때 생성해 별도 보관, 교체·복구 절차를 문서화.
- 비밀번호는 해시, 초대·재설정·봇 토큰은 해시만 저장.
- **마스킹은 처음부터**(단계 2~3): 비밀 변수는 로그·오류 메시지·스텝 결과에서 가리고, 녹화는 비밀번호 입력을 기록하지 않는다. 스크린샷·영상의 개인정보 가림은 단계 7 에서 더하되, 가리지 못하는 형식(영상 등)은 무엇인지 문서에 밝힌다.

### 4.6 계정(메일 없음)
- **첫 관리자**: 설치 후 첫 접속에서 만든다(설치 토큰으로 보호).
- **가입**: 기본은 초대로만. 도메인 제한 자동 가입은 OIDC·GitHub 처럼 이메일 확인이 된 경우에만 허용.
- **초대 링크**: 대상 이메일·워크스페이스·역할 고정, 짧은 만료, 한 번만 사용, 철회 가능.
- **재설정 링크**: 관리자가 발급, 짧은 만료, 한 번만 사용, 사용하면 기존 세션 모두 폐기, 발급 기록을 남김.
- **긴급 복구**: 관리자 계정을 잃으면 서버 운영자가 CLI(`defe2end admin reset`)로 복구.
- 링크 토큰이 로그·Referer 에 남지 않게.
- OIDC 계정은 `issuer + subject` 로 식별. 같은 이메일이라는 이유만으로 로컬 계정과 자동 연결하지 않는다.

### 4.7 AI(로컬 CLI)
- AI 가 없어도 실행·결과·CI·알림은 완결된다. 진단은 사용자가 앱에서 요청하는 별도 기능.
- 진단·채팅에 보내는 정보(DOM·로그·스크린샷)를 화면에 밝히고, 마스킹된 값만 보낸다.
- 테스트 대상 페이지의 글이 AI 에게 로컬 명령·파일 권한을 주지 않게 도구 권한을 제한한다.
- 로컬 CLI 도 모델 요청은 외부로 나간다는 점을 문서에 밝힌다.

## 5. 운영 수명주기

> 운영은 사용자가 한다(1.1). 이 절은 **사용자가 안전하게 운영할 수 있도록 제품이 갖춰야 할 동작**이다.

- **업그레이드**: 버전 고정 이미지, 이전 버전에서 다음 버전으로만 지원(건너뛰기 경로는 릴리스 노트에 명시), 업그레이드 전 백업 안내.
- **백업·복원**: 대상은 DB + 파일 저장소 + 암호화 키 + 설정. 백업은 사용자가 실행하고, 우리는 방법 문서와 일관된 시점을 만드는 명령을 제공한다. 그 절차가 실제로 되는지 **빈 환경 복원 시험**을 우리 릴리스마다 돌린다.
- **작업 큐**: 작업 점유·heartbeat·점유 만료. 실행 중 worker 가 죽으면 그 실행은 `error` 로 끝내고 **자동 재실행하지 않는다**(대상 사이트 동작이 반복될 수 있으므로). 중복 방지 키로 같은 요청 중복 생성 차단.
- **취소**: 취소와 완료가 겹치면 먼저 확정된 쪽이 이긴다(조건부 갱신). 취소 시 Chromium 프로세스까지 종료 확인. PC 실행은 연결이 끊기면 결과를 재전송하고, 시간 안에 안 오면 `error`.
- **스케줄**: 시간대 지정, 서버가 멈춰 놓친 예약은 실행하지 않고 기록, 이전 실행이 아직 돌고 있으면 건너뜀(설정 가능).
- **자원 상한**: 전체·워크스페이스 동시 실행 수, 대기열 길이, 스텝·실행 시간 제한, 디스크가 부족하면 새 실행 거부.
- **보존**: 실행 결과 보존 기간·용량 상한, 고아 파일 정리. 승인된 기준 이미지는 정리 대상에서 제외. 수동 삭제.
- 최소 사양은 측정 후 문서화(그 전 값은 추정으로 표시).

## 6. 버전 호환 계약

- 서버·데스크톱 앱·runner·MCP·스텝 형식에 각각 버전을 둔다.
- 앱이 연결할 때 **지원 기능 목록**을 보내고, 서버는 앱이 모르는 액션·옵션이 든 실행을 **보내기 전에 거절**한다(구버전이 새 옵션을 무시해 "거짓 통과"가 나는 것을 막는다).
- 실행마다 실행 당시의 앱·runner·브라우저 버전과 시나리오 사본을 기록한다.
- 지원 범위: 서버 N 버전은 앱 N-1 까지. 그보다 오래된 앱은 업데이트 안내.

## 7. 설계 원칙

- 도구·API 설명은 계약이다. 설명과 동작이 다르면 버그로 보고 시험으로 확인한다.
- 환경 비교는 비교할 때 화면 허용 오차를 고르고(시각 회귀 허용치와 분리), diff 이미지는 유효한 두 캡처가 있으면 항상 보여 준다. 구조 비교는 요소 단위(순서 이동·한쪽에만·내용 변경 구분, 순서만 바뀌어도 판정은 다름), 링크 도메인 정규화 옵션, 긴 diff 접기.
- 비교·기준 이미지는 OS·화면 크기·글꼴 조건을 기록하고, 조건이 다르면 비교 불가로 표시한다.

## 9. 공개 전 점검

- **클린룸**: 다른 도구의 코드를 보지 않고 동작 요구사항으로 처음부터 쓴다. 기능 요구사항은 이 문서처럼 일반적인 말로 새로 쓰고, 테스트 준비물도 새로 만든다.
- **클린룸 검사**: CI 가 `scripts/cleanroom-check.mjs` 로 저장소에 금지어가 없는지 본다. 금지어 목록(해시)은 저장소 밖(`scripts/cleanroom-hashes.local.txt`, git 에서 제외)에 두고, CI 는 비밀 값 `CLEANROOM_HASHES` 로 받는다.
- **이력까지 점검**: 공개 전 현재 파일뿐 아니라 git 이력·첨부·릴리스 산출물에서 특정 회사·서비스 이름, 내부 URL, 비밀 값을 검사한다.
- **라이선스**: 배포물(컨테이너·설치 파일)마다 의존성 목록(SBOM)과 제3자 고지(Playwright·Electron·Chromium 포함)를 넣는다. AI CLI 는 동봉하지 않고 사용자가 설치한 것을 호출한다.
- **이름**: 공개 대상 국가에서 `defe2end` 상표·유사 명칭·관련 서비스 선행 사용을 확인한다.
- **설치 시험**: 깨끗한 mac·Windows PC 에서 GitHub 다운로드 → 설치 → 실행 → 수동 업데이트. 서명이 없어 회사 정책상 실행이 막히는 환경이 있음을 문서에 밝히고, 보안 기능 전체 해제를 해결책으로 안내하지 않는다. 체크섬 제공.
