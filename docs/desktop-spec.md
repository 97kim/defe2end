# 데스크톱 앱 동작 명세

defE2End 데스크톱 앱의 동작 명세다. 연결·버전 호환, PC 실행, 대상 사이트 로그인 세션, 사이드 브라우저, 녹화, Electron 격리를 다룬다.
서버와 주고받는 API·데이터 모델·담당 경계는 [stage4-contract.md](stage4-contract.md) 가 기준이고, 이 문서는 앱이 어떻게 움직이는지를 적는다. 두 문서가 다르면 계약 문서를 따른다.

---

## 1. 서버 연결·버전 호환

### 1.1 서버 주소
- 첫 실행 때 앱의 로컬 화면에서 서버 주소를 받는다. `https` 만 받고, `http` 는 `localhost`·`127.0.0.1` 만 허용한다. 주소는 origin 만 남기고 끝의 `/` 를 잘라 낸 뒤, `GET {서버}/api/health` 로 defE2End 서버인지 확인하고 저장한다.
- 서버 주소는 앱 설정에서 바꿀 수 있다. 바꾸면 9절(계약 문서)의 순서로 이전 서버의 토큰·세션·사이드 브라우저 데이터를 지운다.
- 미전송 결과 보관함(2.4)은 서버별로 나눈다 — "서버 origin 의 SHA-256 해시" 이름의 하위 폴더. 같은 실행 번호를 다른 서버로 잘못 보내지 않기 위해서다.

### 1.2 인증(앱 ↔ 서버)
- 메인 창은 **서버 웹 UI 를 그대로 로드**한다. 사용자는 그 웹 화면에서 평소처럼 로그인한다(웹 세션 쿠키). 외부 로그인(OIDC·GitHub)은 서버가 알려 준 인증 origin 안에서만 메인 창 이동을 허용한다.
- 앱(메인 프로세스)은 메인 창 세션의 서버 쿠키로 `POST /api/desktop/token` 을 불러 앱 토큰을 받는다. 앱 토큰은 불투명 토큰이고 기기(설치 × 사용자)에 묶이며, OS 보안 저장소에만 둔다. 모든 HTTP 요청과 SSE 에 `Authorization: Bearer` 헤더로 싣는다(쿼리 파라미터로 보내지 않는다).
- 자동 연결: 메인 창이 서버의 로그인 뒤 페이지로 이동하면 토큰 교환과 연결을 시작한다. 동시에 여러 번 불려도 **한 번에 하나만** 돌고, 도는 중에 또 불리면 끝난 뒤 한 번 더 돈다(연결이 둘 생기지 않게).
- 토큰 갱신: HTTP 응답이 **401 이면** 같은 교환으로 새 토큰을 받아 **한 번만** 재전송한다. 403 은 갱신하지 않고 호출자에게 그대로 준다. 동시에 여러 요청이 401 을 받아도 교환 요청은 하나로 공유한다. 이미 새 토큰이 있으면(늦게 온 옛 요청의 401) 교환하지 않고 새 토큰을 쓴다.
- 계정 보호: 새로 받은 토큰의 사용자가 원래와 다르면(로그아웃·계정 전환 중) 진행 중 연결에 넘기지 않는다.
- 종료 중에는 갱신을 멈추고, 마지막 결과 보고는 기존 토큰으로 마무리한다.

### 1.3 SSE(서버 → 앱 push)
- 경로 `GET {서버}/api/desktop/stream`. 요청 헤더로 앱·실행기 버전과 프로토콜(`Defe2end-Client`), 기능 목록(`Defe2end-Capabilities`), 지금 들고 있는 실행 목록(`Defe2end-Active-Runs`)을 보낸다.
- 메시지 종류(JSON, `type` 필드):
  - `connected` — 연결 번호, 최소 앱 버전, 서버 버전, 녹화 설정(테스트 속성 목록). 받으면 연결 표시를 켜고 **미전송 최종 결과를 즉시 재전송**(2.4)한다.
  - `run` — PC 실행 요청(2장). 저장 전 시험 실행도 같은 메시지다(2.6).
  - `capture-auth-state` — 로그인 세션 캡처 요청(3장).
  - `stop-run`(`runId`) — 실행 하나 중지. 전체 중지도 실행마다 이 메시지로 온다.
  - `heartbeat` — 서버가 **30초**마다 보낸다.
- **무응답 감시**: 마지막 메시지(어떤 메시지든) 수신 후 **75초** 동안 아무것도 안 오면 연결을 끊고 즉시 재연결한다.
- **재연결**: 오류가 나면 **5초 + 0~2초 무작위** 뒤 재연결한다. 401 이면 토큰을 다시 교환하고, 426 이면 재연결하지 않고 업데이트 대화상자(1.4)를 띄운다.
- 이전 연결의 늦은 콜백은 세대 번호로 무시한다(재연결 경쟁 방지).

### 1.4 앱 버전 검사·구버전 거절
- 서버가 앱 버전이 최소 버전보다 낮거나 프로토콜이 다르면 연결을 **426**(`app_update_required`)으로 거절한다. 실행에 필요한 액션·기능이 앱에 없으면 실행 생성이 409 로 거절된다.
- 426 을 받으면 앱은 **강제 업데이트 대화상자**를 한 번 띄운다: 버튼 [다운로드 페이지 열기] [종료]. 다운로드 주소는 서버가 알려 준 주소, 없으면 GitHub Releases 다.
- 앱 안 자동 설치는 없다. 새 버전 알림은 앱 시작 때와 하루 한 번 최신 버전을 확인해 띄우고, 설정으로 끌 수 있다.
- 버전 비교: `+` 뒤 빌드 메타 무시, 프리릴리스는 정식보다 낮게 보는 SemVer 비교.

### 1.5 종료·연결 해제
- 창을 닫아도 macOS 는 연결 유지, 그 외는 종료 흐름.
- 종료 요청 시 연결 정리(진행 중 실행 중단 포함)를 **최대 5초** 기다리고 넘기면 강제 종료한다. 두 번째 종료 요청은 기다리지 않고 바로 종료한다.
- 보내지 못한 최종 결과는 디스크 보관함(2.4)에 남아 다음 연결 때 보낸다. 점유 만료 시간이 지난 뒤 도착한 결과는 서버가 반영하지 않는다(2.8).

### 1.6 PC 표시 라벨
- 호스트 이름은 읽지 않는다(실명이 들어가는 경우가 많음). 첫 실행 때 만든 **랜덤 4자**를 앱 데이터 폴더에 저장해 재사용하고, 사용자가 별칭을 적으면 그것을 쓴다(40자까지).
- 표시용일 뿐 어떤 데이터의 키로도 쓰지 않는다.

### 1.7 서버 쪽 동작
- 서버는 연결마다 새 연결 번호를 만들어 기기의 **현재 연결**로 기록한다. 온라인 여부는 마지막 수신 시각으로 정하고, 프로세스 메모리에만 두지 않는다. 기기의 현재 연결이 아닌 스트림은 스스로 닫는다.
- 스트림은 토큰 폐기·만료와 사용자 활성 여부를 계속 확인하고, 실행을 보낼 때마다 요청자의 실행 권한을 다시 확인한다. 세부는 계약 문서 3절.

## 2. PC 실행

### 2.1 받기와 대기열
- `run` 메시지를 받으면 바로 실행하지 않고 **앱 내부 대기열**(메모리)에 넣는다. 동시 실행 기본 **1**. 메시지에 `concurrency`(그룹 실행)가 있으면 그 값으로 바꾸되 **앱 상한 4**.
- 실행 PC 는 요청에서 고른 기기, 고르지 않으면 요청자의 가장 최근 온라인 기기다.

### 2.2 시작 확인(ACK)
- 실행 시작 전에 서버에 시작을 알리고(`POST …/runs/{id}/start`, `Idempotency-Key: run-start-{id}`) **서버가 실행 중으로 옮겼다는 응답과 점유 토큰을 받아야만** 브라우저를 띄운다. 실행 번호마다 브라우저는 한 번만 띄운다.
- 응답이 종료 상태(취소 등)면 실행하지 않고 끝낸다.
- 재시도: 즉시 → 0.5초 → 1.5초 한 묶음, 실패하면 5초·15초·60초(이후 60초 유지) 쉬고 다시 한 묶음. 시작 응답을 받거나 취소될 때까지 대기열 자리를 쥐고 있는다.
- 실행 중에는 **15초**마다 heartbeat 로 점유를 연장한다. 점유를 잃으면(`lease_lost`·404, 또는 응답 없이 만료 10초 전까지 연장 실패) **10초 안에** 실행을 멈추고 남은 결과를 보내지 않는다.

### 2.3 진행 보고
- 스텝 시작·결과를 서버로 보낸다(`(attempt, index)` 로 멱등). 스크린샷·영상·trace·로그는 별도 업로드 경로로 올린다(스크린샷 하나 10MB, 실행 총량 200MB).
- 진행 보고는 **최선 노력**이다: 실패해도 실행을 실패시키지 않고, 유실된 스텝은 최종 결과로 복구된다. HTTP 오류 응답을 성공으로 착각하지 않는다. 종료 중에는 보내지 않는다.

### 2.4 최종 결과
- 판정·중단 원인·시도 수·소요 시간과 **모든 시도의 스텝 결과**를 싣는다. 비밀 값은 싣기 전에 가린다.
- **전송 전에 먼저 디스크에 기록**한다(서버별 보관 폴더, 권한 0700, 파일당 실행 번호 하나, 서버 origin·사용자·기기를 함께 기록). 서버가 2xx 또는 "이미 끝난 실행" 응답을 주면 전송 완료로 보고 파일을 지운다. 404·`lease_lost` 면 격리 폴더로 옮기고 다시 보내지 않는다.
- 재시도: 즉시 → 0.5초 → 1.5초, 실패하면 디스크에 남기고 **하나의 백오프 타이머**(5·15·60초)와 **SSE 재연결(`connected`) 시점**에 다시 보낸다. 앱을 다시 켜면 보관 폴더를 읽어 복구한다. 깨진 파일은 격리 폴더로 옮긴다. 지금 토큰의 서버·사용자·기기와 다른 파일은 보내지 않는다.
- 미전송 최종 결과가 있으면 새 실행 시작을 그만큼 늦춘다(역압).

### 2.5 취소
- `stop-run`: 대기열에 있으면 빼기만 한다(서버가 이미 취소로 확정). 실행 중이면 중단 신호를 보내고 브라우저를 닫는다. 이 앱이 모르는 실행이면 무시한다.
- 실행 중 사용자가 브라우저 창(또는 첫 페이지)을 직접 닫으면 `cancelled` 로 끝내고 다시 시도하지 않는다.

### 2.6 시험 실행
- 저장 전 시험 실행도 같은 `run` 메시지·대기열·결과 경로를 쓴다. 취소도 2.5 와 같다.

### 2.7 영상·브라우저 표시
- 페이지(처음 페이지·새 창)별 영상을 산출물로 올린다. 키는 처음 페이지 `main`, 새 창 `popup-{순번}`.
- PC 실행은 기본으로 브라우저 창을 보여 준다. 앱 설정 "브라우저 숨기고 실행"을 켜면 headless 로 돈다. 이 설정은 PC 의 로컬 설정이다.

### 2.8 서버 쪽 배정·끊김 처리
- 서버는 기기의 현재 연결로만 실행을 보낸다. 점유가 만료되면 그 실행은 `error`(`desktop_lost`)로 끝나고 다시 돌지 않는다.
- 재연결 때 서버는 앱이 보낸 실행 목록과 대조한다. 이전 연결로 보냈는데 목록에 없는 실행은 대기면 `error`(`desktop_reconnected`), 실행 중이면 `error`(`desktop_lost`)다. 세부는 계약 문서 4절.

## 3. 대상 사이트 로그인 세션

### 3.1 만드는 두 경로
1. **캡처 창**: 웹 UI 의 "로그인 세션 만들기" 로 서버가 `capture-auth-state`(환경)를 보내면 앱이 **화면 있는 별도 Chromium** 을 띄워 사용자가 직접 로그인한다. **2.5초마다** 저장 상태(쿠키·localStorage) 스냅샷을 갱신하고, 창(또는 탭)을 닫으면 닫기 직전 한 번 더 찍어 마지막 성공 스냅샷을 서버에 등록한다. 새 캡처 명령이 오면 기존 캡처는 등록 없이 정리한다. 등록이 실패하면(4xx 제외) **2초 뒤 1회** 재시도한다.
2. **사이드 브라우저에서 저장**: 사용자가 이미 로그인한 사이드 브라우저 탭에서 "이 사이트 로그인 저장"을 누르면, 현재 탭 URL 의 host 기준으로 **대상 host 자신 또는 상위 도메인 쿠키만** 거른다(무관 사이트 세션 제외). localStorage 는 현재 origin 것만, 문자열 쌍만 남긴다(읽기 실패 시 쿠키만). SameSite 미지정은 Lax 로 맞춘다. 세션 쿠키는 만료 -1. 대상 쿠키가 하나도 없으면 "로그인 후 다시" 안내하고 등록하지 않는다.
- 공통: 등록은 `POST {서버}/api/desktop/auth-sessions`, 소유자는 토큰의 사용자다. **쿠키 값·토큰은 어떤 로그에도 남기지 않고 개수만** 남긴다. 쿠키 0개 스냅샷은 로그인 결과로 보지 않는다.

### 3.2 쓰기
- 로그인 세션을 쓰도록 설정한 환경의 PC 실행은 `run` 메시지에 **요청자 본인의 세션**이 실려 온다. 앱은 실행마다 새 브라우저 컨텍스트를 만들 때 넣고, 메모리에만 둔다(디스크·로그·이벤트에 싣지 않음).

### 3.3 저장·키 범위·만료(서버)
- 서버에 설치 키로 암호화해 저장한다. 키 범위는 **환경 × 사용자**, 크기 상한 512KB.
- 만료: 저장 30일 또는 대상 쿠키의 만료 시각 중 이른 쪽. 만료된 세션은 없는 것으로 본다.
- 세션이 필요한 환경에서 요청자 본인의 유효한 세션이 없으면 실행 생성이 409(`auth_session_missing`)로 거부된다. 다른 사람의 세션으로 대신하거나 실행 위치를 바꾸지 않는다.

## 4. 사이드 브라우저

- **형태**: 메인 창 안의 네이티브 뷰(탭 여러 개). 각 탭은 별도 뷰, 활성 탭만 보인다. 서버 웹 UI 가 그리는 영역 좌표를 받아 그 위에 얹는다. 패널 경계 드래그 중에는 잠깐 숨긴다.
- **열기**: 웹 UI 가 열기 요청(선택 URL·영역). HUD·찾기 바를 탭보다 먼저 만들고, 탭이 없으면 새 탭(URL 없으면 about:blank), 있으면 기존 탭 재사용(재진입 시 URL 로 덮어쓰지 않음).
- **닫기**: 모든 탭 뷰를 떼고 닫는다(DevTools·HUD·찾기 바도 정리). 다시 열면 새 탭에서 시작. **최소화**는 뷰를 살려 두고 숨기기만 한다(세션·상태 유지).
- **새 창 요청**(target=_blank 등): 원래 동작은 막고 앱 안 새 탭으로 열어 활성화한다. 녹화 중이면 "누가 열었는지" 계보를 남긴다(5장).
- **세션 저장소**: 탭은 사이드 브라우저 **전용 영구 파티션** 하나를 쓴다. 서버 웹 UI(메인 창)와 쿠키·저장소가 섞이지 않고, 탭끼리는 공유한다. 닫거나 앱을 다시 켜도 남는다. 앱 설정의 "사이드 브라우저 데이터 지우기"로 지울 수 있고, 서버 주소를 바꾸거나 로그아웃·계정 전환 때 자동으로 지운다.
- 권한 요청(알림·위치·카메라 등)은 모두 거절하고, 다운로드는 막는다.
- **찾기 바**: 활성 탭 위에 뜨는 로컬 화면이 검색어를 보내고 일치 수를 받는다.
- **기기 보기**: 모바일 보기(360×780)는 화면 크기·UA 를 맞추고, 새 탭 첫 요청은 에뮬레이션이 붙은 **뒤에** 보낸다. 녹화 중에는 기기 전환 금지.

## 5. 녹화

### 5.1 시작·정지
- 사이드 브라우저에서만. 시작 시 활성 탭·현재 URL·현재 기기(데스크톱/모바일)를 기록한다. 모든 탭·모든 프레임에 녹화 모드를 켜고 대화상자 감시를 넣는다. 새 탭·이동으로 페이지가 다시 뜨면 준비 신호에 맞춰 녹화 상태를 다시 적용한다.
- 시작 탭과 **시작 탭이 연 새 창 계보**만 변환한다. 사용자가 직접 연 다른 탭 이벤트는 제외하고 건수만 경고한다.
- HUD(녹화 카드): 시작 즉시 빈 카드(0개), 이벤트마다 스텝 수·마지막 스텝 이름·액션 갱신, 정지 시 사라진다.
- 시간·스텝 수 상한은 없다. 이벤트는 정지할 때까지 쌓이고 정지하면 비운다.

### 5.2 셀렉터 후보(이 순서로 쌓고 재정렬)
1. 역할(이름): 역할이 link·button·heading 일 때만. 이름에 `)` 있으면 만들지 않는다. aria-label·alt·title 이 있으면 그것, 없으면 본문 텍스트(30자 이하이고 안에 조작 요소 없을 때). 카드형 링크는 안의 제목 텍스트(30자 이하).
2. `#id` — id 앞부분(영숫자·`_`·`-` 연속 구간)에 **숫자 4자리 이상 연속**이 있으면 동적 id 로 보고 제외.
3. `[data-testid="…"]`
4. 테스트 속성: 서버 설정 "테스트 속성 목록"(`connected` 메시지로 받음)의 속성을 목록 순서대로 보고, 처음 있는 것으로 `태그[속성="값"]`. 목록이 비어 있으면(기본) 건너뛴다.
5. `태그[name="…"]`
6. `input[placeholder="…"]`(태그 무관 항상 input)
7. href 부분 일치 `a[href*="…"]`: href 길이 2 이상, `javascript` 로 시작하지 않을 때. **쿼리·해시 뗀 경로 후보를 원문보다 먼저**(같으면 하나). 80자로 자르고 `"` 제거. 광고·추적 URL(추적 도메인, 리다이렉트 경로, `gclid`·`fbclid` 파라미터)은 href 후보 없음. 경로가 `/` 뿐이면 경로 후보 없음.
8. 안정 클래스: `태그.클래스1`, 클래스 둘 이상이면 `태그.클래스1.클래스2`(긴 클래스부터). 제외: 3자 미만, `sc-`·`css-`·`jsx-` 접두, 숫자 섞인 난수형, 3~8자 대소문자 혼합 토큰, 모음 없는 4~10자 소문자, 상태 조각(active·hover·focus·focused·selected·checked·current·open·opened·expanded·collapsed·disabled·highlight·highlighted, `-`·`_` 로 나눈 조각 기준).
9. `text=이름`: 25자 이하일 때(접근성 이름은 공백 정리 후 40자 자름). 위 후보가 하나도 없으면 길이 무관 마지막 보루.
- **재정렬**: 실제 DOM 일치 개수로 등급 — 1개 일치 또는 셀 수 없는 것(`text=`) 0등급, 여러 개 1등급, 0개 2등급. 같은 등급은 원래 순서 유지. 역할 후보는 정확 일치로 센다. **첫 번째 후보만** 스텝에 쓴다(나머지 후보는 저장 전 제거하는 내부 필드).
- nth·조상 경로(CSS path) 폴백은 **없다**.
- 클릭 대상은 가장 가까운 조작 가능 조상으로 올린다: a, button, 역할 button·link·tab·option·menuitem, input, select, textarea, label, onclick 속성 요소.

### 5.3 이벤트별 기록 시점
- **입력**: `change`(포커스 이탈·확정)와 Enter 때만. input 이벤트·디바운스 없음. checkbox·radio·button·submit·file 은 입력 제외. 같은 요소 같은 값 연속은 한 번. 변환 시 직전 스텝이 같은 셀렉터 입력이면 값만 덮어쓴다(iframe 입력도 동일).
- **클릭**: select 클릭 제외(change 가 담당). input·textarea 는 button·submit·checkbox·radio·image·file 타입만. 같은 셀렉터 **800ms 미만** 연속 클릭은 하나로. `position: fixed/sticky` + z-index **1000 이상** 오버레이 안 클릭은 "조건부" → optional, timeout 5000, 이름 끝 "(조건부)".
- **선택**: change 에서 선택된 option 의 label 을 값으로.
- **키**: Enter 만(입력칸에서, 그 전에 입력 스텝 먼저). IME 조합 중 Enter(조합 중 표시 또는 keyCode 229) 무시. iframe 안 키는 경고 후 건너뜀.
- **이동**: 메인 프레임 이동만(기기 전환 리로드 제외). 조작 뒤 이동 → URL 대기(`*경로*`, 30초) + URL 검증 두 스텝. 조작 없이 이어지는 이동은 리다이렉트로 보고 직전 URL 스텝의 도착지만 갱신. 경로가 `/` 이거나 직전과 같으면 URL 스텝 대신 다음 조작 앞에 요소 노출 대기(30초).
- **스크롤**: 마지막 스크롤 후 **600ms** 잠잠하면 정지점 하나. 맨 위/아래 판정 여유 **40px**. 연속 정지점은 마지막만(맨 아래 반복은 각각). 맨 아래 → `bottom`, 맨 위 → `top`(이미 맨 위면 없음), 그 외 직전 위치와의 px 차이(0 이면 없음). 이동 후 기준 0. iframe 내부 스크롤 무시.
- **호버**: 자동 추론 없음. 녹화 중 우클릭 메뉴에서 사용자가 고른 경우만. 호버 뒤 **10초** 안의 클릭 앞에 노출 대기(10초) 삽입.
- **우클릭**: 페이지 메뉴를 막고 요소를 600ms 강조, 웹 패널에 검증 추가 요청. 종류: 보임 확인, 보임 확인(경고만), 텍스트 확인, 호버. 대상 텍스트는 앞 80자.

### 5.4 대화상자·팝업·iframe
- **대화상자**: 페이지의 alert/confirm/prompt 를 감싸 결과·뜬 시각을 기록. 직전 스텝이 클릭이고 그 뒤 **2000ms** 안에 뜬 것만 그 클릭에 합친다(없으면 경고). alert·확인한 confirm → `clickAndAcceptDialog`(이름 끝 " + 확인"), 취소한 confirm → `clickAndDismissDialog`(" + 취소"), 확인한 prompt → `clickAndSubmitPrompt`(값 포함, " + 입력"). 사이드 브라우저는 prompt 를 띄우지 못하므로 prompt 는 "직접 추가하세요" 경고만 남긴다.
- **팝업**: 시작 탭이 직접 연 새 창만(손자 창은 경고 후 제외). 새 창을 연 직전 클릭이 **2000ms** 안이고 바로 앞 스텝이면 `clickAndWaitPopup` 으로 승격(" + 새 창"); 없으면 팝업 구간 전체를 버리고 경고. 팝업 안에서는 클릭·입력·보임 확인·팝업 URL 확인만 만들고(이동은 첫 도착 URL 만 검증), 나머지(키·스크롤·대화상자·선택·호버·텍스트 확인·iframe)는 종류별 건수 경고. 팝업 열린 동안 원래 탭 조작도 건수 경고. 팝업 닫기 → `closePopup` 스텝, 끝까지 안 닫으면 마지막에 자동으로 넣고 경고.
- **iframe**: 모든 프레임에서 기록(하위 프레임 여부·프레임 URL 포함). 프레임 지정은 `iframe[src*="프레임 경로 앞 60자"]`, 경로가 `/` 뿐이면 경고 후 건너뜀. 클릭 → `clickInIframe`(값=안쪽 셀렉터), 입력 → `fillInIframe`(입력값은 expected). iframe 안 선택·키는 경고 후 건너뜀.

### 5.5 비밀번호
- `type=password` 속성만으로 판정. 값은 항상 `{{PASSWORD}}` 로 치환(팝업 입력 포함)하고, 원문은 이벤트·후보에 싣지 않는다. 원문 값이 든 셀렉터 후보도 걸러 낸다. 표시 이름은 placeholder, 없으면 "비밀번호".

### 5.6 결과의 행방
- 녹화 중 이벤트가 쌓일 때마다 **전체를 다시 변환**해 웹 UI 녹화 패널로 보낸다: 스텝, 스텝마다 그 스텝을 만든 원천 이벤트 목록, 경고, origin, 이벤트 수, 기기. 정지하면 같은 구조를 돌려준다.
- 저장은 **사용자가 웹 UI 에서** 기존 시나리오 API 로 한다. 앱이 서버에 직접 저장하지 않는다.
- 뼈대: 첫 스텝 `goto`("시작 페이지", 시작 URL 의 경로; origin 은 따로 반환), 마지막 스텝 `screenshot`("최종 화면").
- 스텝 이름: "「텍스트 앞 20자」" + " 클릭"/" 입력"/" 선택"(텍스트 없으면 "요소"·"필드"·"셀렉트"·"입력").
- 녹화 중 스텝 삭제는 스텝이 아니라 **그 스텝을 만든 원천 이벤트를 버리고 전체 재변환**한다.
- 출력 스텝은 [action-spec.md](action-spec.md) 의 액션 이름 그대로이고, 스텝 스키마를 통과하지 못하는 스텝은 만들지 않는다.

## 6. Electron 격리

- 모든 뷰: `contextIsolation` 켬, `sandbox` 켬, `nodeIntegration` 끔.
- 메인 창: 서버 URL 을 로드하고 preload 하나. 이동은 서버 origin 과 허용된 인증 origin 안에서만, 그 밖의 `http(s)` 링크는 시스템 브라우저로, 그 밖 스킴은 막는다. 새 창은 막는다. 권한 요청은 모두 거절한다.
- 사이드 브라우저 탭: 녹화 preload 가 iframe 안에서도 돌도록 `nodeIntegrationInSubFrames` 를 켠다. preload 는 Node API 없이 `ipcRenderer` 만 쓴다. 전용 파티션(4장).
- HUD·찾기 바 뷰: 각자 작은 preload, 로컬 화면만.
- **메인 창 preload API**(이것만): 연결(상태 구독·연결·해제·로그아웃·별칭), 사이드 브라우저(열기·닫기·영역·이동·기기·탭·세션 저장), 녹화(시작·정지·이벤트 버리기·검증 추가·이벤트 구독), 실행 진행 구독, 앱(버전·서버 주소 바꾸기).
- **IPC 발신자 검사**: 메인 창 발 IPC 는 메인 프레임이고 발신 프레임 origin 이 저장된 서버 origin 일 때만 처리한다. 예외는 첫 실행 화면의 주소 설정 하나로, 정확한 로컬 번들 URL 의 메인 프레임에서만 받는다. 사이드 브라우저 발 IPC 는 알려진 탭의 webContents 인지 확인한다. 어긋나면 무시하고 로그를 남긴다.
