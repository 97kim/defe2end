# 변수 계약 — 공유·개인

> 2026-10-13. 변수를 계정마다 따로 쓸 수 있게 바꾼다. 바꾸려면 이 문서부터 고친다.
> 상위 문서: [plan.md](plan.md) 4.5절, [stage2-contract.md](stage2-contract.md)(변수 쓰기 전용·가림), [stage4-contract.md](stage4-contract.md) 5절(로그인 세션은 요청자 본인 것만). 변수 동작의 세부는 [variable-spec.md](variable-spec.md).

## 0. 결정 (2026-10-13)

- **변수마다 범위를 정한다**: `shared`(공유 — 환경에 값 하나, 지금과 같음) 또는 `personal`(개인 — 사람마다 자기 값).
- 개인 변수는 **실행 요청자 본인 값만** 쓴다. 내 값이 없으면 공유 값이나 남의 값으로 넘어가지 않고 **명시 오류**다(단계 4 로그인 세션과 같은 원칙).
- 키 범위는 지금처럼 **환경 단위**(로그인 세션과 같음).
- 비밀 여부는 지금처럼 변수 정의의 표시(`isSecret`)로 정하고, 개인 값에도 같이 적용된다(비밀이면 암호화·쓰기 전용).
- 사람 요청자가 없는 실행(스케줄·봇 토큰)은 사람의 개인 값을 쓰지 않고, **스케줄·봇 토큰에 따로 넣은 개인 변수 값**을 쓴다(2026-10-14, [stage5-contract.md](stage5-contract.md) 1.1절). 없으면 같은 명시 오류.

## 1. 데이터 모델 (`packages/db`, 새 마이그레이션 — 리드)

| 모델 | 변경 |
|---|---|
| `Variable` | `scope`(`shared` 기본·`personal`) 추가. 개인 변수의 `value`·`valueEncrypted` 는 늘 null(정의만 둔다). 고유(environmentId, key) 유지 |
| `PersonalVariableValue`(새) | `variableId`, `userId`, `value?`, `valueEncrypted?`(변수가 비밀이면 이쪽만), `updatedAt`. 고유(variableId, userId). 변수·사용자가 지워지면 같이 지운다 |

- 범위를 바꾸면: `shared → personal` 은 공유 값을 지우고, `personal → shared` 는 모든 개인 값을 지운다. 화면은 바꾸기 전에 확인을 받는다.
- 비밀 표시를 바꾸면: **개인 변수**는 모든 개인 값을 지운다. **공유 변수**는 지금 동작을 유지한다(평문→비밀은 값을 암호화해 남기고, 비밀→평문은 새 값을 요구). 어느 쪽도 평문·암호문이 섞이지 않는다.

## 2. 권한 (`can()` — 리드)

- 변수 정의(만들기·범위·비밀 표시·이름·삭제)와 공유 값 쓰기: 지금과 같은 `config.write`(EDITOR 이상).
- 개인 값 쓰기·지우기: 새 `variable.personal.write`(EDITOR 이상, **본인 값만**). 읽기는 본인 값만(비밀이면 `hasValue` 만).
- 남의 개인 값은 어떤 API·화면·내보내기·로그에도 나오지 않는다. 다른 사람이 값을 넣었는지 여부도 보이지 않는다(관리자 포함).

## 3. 실행 때 값 결정

- **생성 때 검사**(실행·시험 실행·그룹 실행·재실행 모두, 단계 3 의 하나뿐인 생성 함수): snapshot 스텝이 참조하는 `{{KEY}}` 중 **개인 변수인데 요청자 값이 없는 것**이 있으면 **409 `variable_missing { keys }`**(웹 공통 오류 형식). 요청자가 사람이 아니면(스케줄·봇) 개인 변수를 참조하는 것만으로 같은 오류.
- **실행 시작 때 해석**(worker 서버 실행, PC 실행의 `run` 메시지 둘 다 같은 함수): 공유 변수는 환경 값, 개인 변수는 `requestedById` 의 값. 생성 뒤 값이 지워져 시작 때 없으면 그 실행은 `error(variable_missing)`(새 `RUN_ERROR_CODES`). 해석 결과의 값은 지금처럼 메모리에만, 비밀은 가림 대상.
- 변수로 정의되지 않은 `{{KEY}}`, 값이 빈 공유 비밀 변수의 기존 동작(액션 명세 2.6 — 그대로 두기·`missing_secret`)은 바꾸지 않는다.
- 실행 결과에 쓰인 변수 키와 범위만 기록할 수 있다(값은 기록하지 않는다).

## 4. API (`apps/web`)

- 환경 변수 목록: 변수마다 `scope` 를 주고, 개인 변수는 공유 값 대신 **요청자 본인 값 상태**(`mine: { hasValue, value? }` — 비밀이면 `value` 없음)를 준다.
- 변수 만들기·고치기에 `scope`. 범위·비밀 표시 변경은 1절 규칙대로 값을 지운다.
- 개인 값: `PUT /api/w/[slug]/variables/[variableId]/mine { value }`, `DELETE …/mine`. 공유 변수에 부르면 409. 남의 워크스페이스·없는 변수는 404.
- 내보내기·가져오기: 변수 정의(키·범위·비밀 표시)만, 공유 비밀 값과 **모든 개인 값은 빠진다**. 가져온 개인 변수는 각자 값을 채운다.

## 5. 화면

- 환경의 변수 표에 "범위" 열(공유/개인). 개인 변수 행은 값 칸이 **"내 값"** 이고, 비어 있으면 "내 값이 없어요 — 이 변수를 쓰는 실행은 막혀요" 안내.
- 실행·시험 실행 대화상자에서 `variable_missing` 이면 빠진 키 목록과 "내 값 넣기" 이동.
- 영·한 문구, A′ Ink 규칙.

## 6. 시험

- 생성 때 409(개인 값 없음, 남의 값만 있음, 공유 값만 있는 이름이 같은 경우도 넘어가지 않음), 요청자별 다른 값으로 실행(서버·PC 각각), 시작 전 값 삭제 → `error(variable_missing)`, 범위·비밀 표시 변경 시 값 삭제, 남의 개인 값 비노출(목록·내보내기·로그), 권한(VIEWER 쓰기 403·남의 것 404), 사용자 삭제 시 개인 값 삭제.
