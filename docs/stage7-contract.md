# 단계 7 계약 — 화면 품질

> 2026-10-16. 단계 7(시각 회귀·스크린샷/영상 마스킹·환경 비교)을 여러 사람이 나눠 만들 때 서로 맞춰야 하는 결정. 바꾸려면 이 문서부터 고친다. 같은 날 구현 전 검토(14건)를 반영했다.
> 상위 문서: [plan.md](plan.md) 4.6·6·7절, [action-spec.md](action-spec.md)(`screenshot` 의 `threshold`·`mask`, 2.11 입력 직전 가림, 스텝 상태), [stage3-contract.md](stage3-contract.md)(실행·산출물), [stage4-contract.md](stage4-contract.md)(앱 실행·기능 목록), [stage5-contract.md](stage5-contract.md)(봇 API `failOnWarning`).

## 0. 완료 기준 (plan 8절)

- 시각 회귀: **기준 없음**(첫 실행이 기준을 만든다), **승인**(사람이 새 기준으로 교체), **허용치 경계**(같으면 일치), **조건이 다른 실행**(기기·실행 환경·렌더링 조건이 다르면 다른 기준 또는 비교 불가), 서버·앱 실행 각각 시험이 통과한다.
- 마스킹: 사이트 셀렉터·자동 감지·스텝 추가 영역이 스크린샷에서 가려지고, 가림을 적용할 수 없으면 찍지 않는다. 영상에 반영되는 범위와 가리지 못하는 형식을 문서에 밝힌다.
- 환경 비교: 같은 시나리오를 한 사이트의 두 환경에서 같은 조건으로 실행해 화면·구조를 비교하고, 목록·상세에서 볼 수 있다. 조건이 다른 실행·마스킹 실패·한쪽 실패는 "비교 불가"로 보인다.

## 1. 결정 (2026-10-16)

| 항목 | 결정 |
|---|---|
| 기준 키 | 시나리오 × **스텝 ID** × 환경 × 기기(뷰포트) × 실행 환경(`server` / `desktop-mac` / `desktop-windows`). 스텝을 넣거나 빼도 다른 스크린샷의 기준이 어긋나지 않는다 |
| 렌더링 조건 | 기준과 캡처마다 브라우저 버전·기기 배율·뷰포트·글꼴 묶음 식별자·마스킹 정책 버전을 기록한다. 기준과 다르면 판정은 `incomparable`(경고 아님, 사유 표시). 키에는 넣지 않는다 — 브라우저가 업데이트될 때마다 기준이 새로 생기면 회귀를 놓친다 |
| 기준 저장 | 기준 이미지는 **별도 사본**(실행을 지워도 남는다). 교체된 기준은 지우지 않고 버전으로 남긴다. 그 버전을 참조하는 스텝 결과가 없고 최신 5개 밖이면 정리 대상 |
| 첫 기준 | 기준이 없으면 그 실행의 스크린샷이 기준이 된다(판정 `created`, 승인자 없음, 화면에 "첫 기준으로 저장됨"). 실패한 스크린샷 스텝은 기준을 만들지 않는다 |
| 기준 교체 | 사람의 **명시적 승인**만. "최근 통과"를 자동 기준으로 삼지 않는다 |
| 판정 영향 | `changed`·`size_mismatch` 는 스텝 **경고**(실행은 통과로 끝나고 경고 수에 들어간다). 봇 API `failOnWarning` 이면 CI 에서는 실패(단계 5 그대로) |
| 수치 | 허용치 = 스텝 `threshold`(기본 5%). SSIM 하한 0.95, 픽셀 색 감도 0.05 는 인스턴스 상수. **판정은 반올림 전 원값으로**, 표시만 반올림 |
| 승인 권한 | `scenario.write`, 워크스페이스 경계는 모든 경로에서 `can()` |
| 마스킹 단위 | 사이트 셀렉터 목록 + 시나리오 켜기/끄기(기본 켜짐) + 스크린샷 스텝 `mask`. 환경 단위 구분은 두지 않는다 |
| 자동 감지 | 기본 켜짐. 이메일·전화번호(국내·국제)·카드번호·주민등록번호 형식 |
| trace | 마스킹이 켜진 실행(기본)에서는 trace 를 만들지 않는다(trace 의 DOM 사본은 가릴 수 없다) |
| 환경 비교 | 시나리오 1개 × 같은 사이트의 환경 2개, 기능 기본 켜짐. 그룹·스케줄 비교·비교 알림은 이번 범위 밖 |
| 비교 조건 | 두 실행은 같은 실행 위치, 앱이면 **같은 기기**. 양쪽 렌더링 조건이 다르면 그 비교는 `incomparable` |
| 구조 비교 | **요소 단위**: 순서 이동·한쪽에만·내용 변경을 구분해 보인다. 순서만 바뀌어도 판정은 "다름" |
| 링크 정규화 | 기본 켜짐: 링크 값이 그쪽 환경 기본 주소의 origin 으로 시작할 때만 그 origin 을 `{origin}` 으로. 숫자·날짜는 정규화하지 않는다 |
| 지우기 | 일반 실행처럼 기준·비교는 지우는 기능을 두지 않는다(시나리오·환경을 지우면 함께 지운다). 비교 자식은 시험 실행 보관 정리 대상이 아니다 |

## 2. 데이터 (`packages/db` — 리드 선행)

- `VisualBaseline`: `workspaceId`, `scenarioId`, `stepId`, `environmentId`, `device`(기기 이름·뷰포트 정규화 키), `runtime`, `currentVersion`. (시나리오·스텝 ID·환경·기기·실행 환경)으로 유일. 시나리오·환경을 지우면 함께 지운다.
- `VisualBaselineVersion`: `baselineId`, `version`(1부터), `storageKey`(사본), `width`·`height`, `render`(렌더링 조건 JSON), `source`(`auto`·`approved`), `approvedById?`, `sourceRunId?`·`sourceStepResultId?`(지워지면 비움), `createdAt`. (기준, 버전)으로 유일.
- `StepResult` 에 더함: `visualVerdict?`(`created`·`match`·`shifted`·`changed`·`size_mismatch`·`skipped`·`incomparable`), `visualDiffPercent?`(원값), `visualSsim?`, `visualBaselineVersionId?`(그 판정에 쓴 버전 — 보존 근거), `render?`(이 캡처의 렌더링 조건).
- `Site.maskSelectors`(문자열, 기본 빈 값), `Scenario.maskingEnabled`(기본 true), 마스킹 정책 버전 상수(`packages/shared`).
- `EnvComparison`: `workspaceId`, `scenarioId`, `siteId`, `leftEnvironmentId`·`rightEnvironmentId`, 해석된 좌·우 기본 주소, `location`·`deviceId?`, `conditions`(실행 조건 사본: 스텝·기기·차단 주소·마스킹 설정·세션 사용 여부·허용 오차·SSIM 하한·제한값·형식 버전 — **변수 값·세션 내용은 넣지 않는다**), `status`(`running`·`comparing`·`done`·`error`·`cancelled`), `round`, `claimToken?`·`claimExpiresAt?`, `tolerance`, `screenVerdict?`·`structureVerdict?`(`same`·`different`·`incomparable`), `error?`, `createdById`, 시각들.
- `EnvComparisonStep`: (비교, 스텝 ID, `round`)로 유일, 좌·우 원본 스텝 결과 ID, 화면 판정·차이 비율·SSIM·적용 허용 오차·diff 저장 키, 구조 판정·이동/추가/삭제/변경 수·diff 저장 키, 사유.
- `EnvComparisonFile`: 비교가 만든 파일(diff 이미지·구조 diff)의 `storageKey`, `comparisonId`, `round`, 종류. 실행 점유가 끝난 뒤 생기므로 실행 산출물(`Artifact`)이 아니라 이 표에 둔다.
- `Run` 에 더함: `comparisonId?`, `comparisonSide?`(`left`·`right`). 비교 자식 실행은 일반 실행 목록·대시보드·시나리오 최근 실행·알림·실패 재실행·시험 실행 정리에서 빠진다.
- 산출물 종류 더함: `visual_diff`(시각 회귀 diff, 실행 중 업로드), `a11y_snapshot`(구조 캡처 원문).
- **고아 파일 정리**(`findUnregisteredKeys`): `VisualBaselineVersion`·`EnvComparisonFile` 의 저장 키도 등록된 것으로 본다. 파일을 먼저 쓰고 행을 나중에 만드는 순서라, 행 생성에 실패한 파일은 다음 정리에서 지워진다(정리는 오래된 파일만 — 기존 규칙).

## 3. 비교 엔진 (`packages/shared` — 리드 선행)

- 입력 두 PNG. 순서: 크기가 다르면 `size_mismatch`(차이 100%) → 크기 0 이면 `match` → 픽셀 비교(색 감도 0.05)로 차이 비율(다른 픽셀 / 전체 × 100, **원값**) → **≤ 허용치면 `match`** → 넘으면 SSIM(그레이스케일, 짧은 변 256 기준 축소) → **≥ 0.95 면 `shifted`**, 아니면 `changed`.
- **diff 이미지**: 시각 회귀는 `shifted`·`changed` 에서 만든다. 환경 비교는 유효한 두 캡처가 있으면 **판정과 무관하게 항상** 만든다(크기가 다르면 두 이미지를 같은 캔버스에 겹쳐 그린다)(plan 7절).
- 환경 비교 판정: `match`·`shifted` → `same`(허용 오차가 0 이면 `shifted` 와 차이가 0 보다 큰 `match` 도 `different`), `changed`·`size_mismatch` → `different`.
- 서버·앱이 같은 코드로 판정한다. 큰 이미지에서 이벤트 루프를 오래 막지 않는다(워커 스레드 또는 나눠 계산).

## 4. 시각 회귀 흐름

- 대상은 **통과한 `screenshot` 스텝**뿐이다. 다른 스텝의 자동 캡처·실패 화면은 비교하지 않는다.
- **기준 고정**: 실행을 만들 때(앱 실행은 배정할 때) 그 실행에 쓸 기준 버전 목록을 정해 실행 사본에 넣는다. 그 실행의 판정은 끝까지 이 버전으로 한다. 실행 도중 승인이 있어도 그 실행의 경고는 그대로다(다음 실행부터 새 기준).
- **기준 내려받기**(앱): 기준 이미지는 앱 API 로만 받는다 — `GET /api/desktop/runs/{runId}/baselines/{versionId}`, 앱 토큰 인증, 서버가 (실행이 그 기기·사용자에게 배정됨, 실행이 진행 중, 버전이 그 실행의 고정 목록에 있음)을 확인한다. 서명 주소를 쓰지 않는다. 응답 크기 상한 20MB, 리다이렉트 따라가지 않음. 서버 실행은 저장소에서 바로 읽는다.
- **첫 기준 경합**: 기준이 없던 키는 판정 `created` 로 올린다. 서버는 기준 행을 만들 때 유일 제약으로 하나만 이기게 하고, 진 쪽은 이긴 기준(버전 1)과 서버에서 다시 비교해 그 판정으로 바꿔 기록한다(둘 다 `created` 가 되지 않게).
- **앱 판정**: 서버는 앱의 판정을 받아들이되(같은 사용자의 PC), 판정이 가리키는 기준 버전이 그 실행의 고정 목록에 있고 같은 워크스페이스·키인지 확인한다. 아니면 그 판정은 버리고 `skipped`.
- 렌더링 조건이 기준 버전과 다르면 `incomparable`(사유: 다른 브라우저 버전·배율·글꼴). 기준을 읽지 못하거나 비교가 예외로 끝나면 `skipped`. 둘 다 실행을 깨뜨리지 않는다.
- 경고 문구(스텝 오류란): 차이 비율·SSIM 또는 기대 크기, "의도한 변경이면 실행 상세에서 새 기준으로 승인하세요".
- **승인**: `POST .../runs/{runId}/steps/{stepResultId}/approve-baseline { expectedVersion }`. 스텝 결과 ID 로 정확히 그 시도의 화면을 고른다. 기준 행을 잠그고 현재 버전이 `expectedVersion` 과 같을 때만 새 버전을 만든다(다르면 409 — 그 사이 다른 승인이 있었음). 같은 스텝 결과로 이미 만든 버전이 현재면 그대로 200(다시 눌러도 같음). 거절: 스크린샷 없음 400, 없는 실행·스텝 404, 환경 비교 자식 409, 실패한 스텝 409, 렌더링 조건이 기록되지 않은 결과 409.
- 결과 화면: 판정 배지(변경·크기 다름 = 경고색, 미세 이동 = 회색, 일치, 건너뜀, 비교 불가 + 사유, 첫 기준), `shifted`·`changed` 는 기준 | 현재 | diff 를 나란히 보이고 승인 버튼. 과거 결과는 그 결과가 쓴 기준 버전을 보인다.
- 알림: 경고 스텝 수와 실행 링크(이미지는 싣지 않는다).

## 5. 마스킹

- **적용 시점**: 브라우저 컨텍스트를 만든 직후 첫 이동 전에 페이지 초기화 스크립트로 심는다(팝업·새 탭·같은 출처 iframe 포함). 셀렉터 가림은 DOM 변화마다 **즉시**, 자동 감지는 디바운스(100ms, 계속 바뀌는 페이지에서도 최대 300ms 안에 한 번은 돌게). 입력값 변경(`input` 이벤트)도 감지 대상이다. 값 입력 직전(action-spec 2.11)과 **캡처 직전**에 한 번씩 강제로 적용한다.
- **셀렉터 검증**: 쉼표·줄바꿈 구분, 괄호·대괄호·따옴표 안 쉼표는 구분자가 아님, 앞뒤 공백 제거, 빈 항목 버림(`packages/shared` 파서, 서버·앱·웹 공용). **저장할 때** 각 셀렉터의 문법을 검사해 잘못된 것이 있으면 저장을 거부한다(400, 몇 번째 항목인지). 스텝 `mask` 도 시나리오 저장 때 같은 검사.
- **촬영 거부**: 캡처 직전 가림을 적용하지 못하면(셀렉터 오류, 스크립트 주입 실패, 시간 초과) 그 스크린샷은 찍지 않는다. 스크린샷 스텝은 `failed`(사유 "가림을 적용하지 못해 찍지 않았어요"), 실패 화면 캡처는 건너뛴다. 가림 없이 찍어 두는 경로는 없다.
- **가리는 방법**: 화면에서는 대상 요소에 블러(10px), 입력창·텍스트 영역은 글자를 점으로. DOM 텍스트 값은 바꾸지 않는다(텍스트 검증이 깨지면 안 됨). 스크린샷은 캡처 시점에 가림 영역(사이트 셀렉터 + 자동 감지 + 스텝 `mask` + 비밀번호·카드 입력칸)을 단색 상자로 덮는다.
- **시나리오 끄기**: 사이트 셀렉터·자동 감지를 끈다. 스텝 `mask`, **비밀번호·카드 입력칸 가림**, 비밀 값 입력 가림(기존)은 끄지 않는다. 편집기에 꺼져 있다는 표시를 한다.
- **자동 감지**: 텍스트 노드 4,000개까지, 3,000자 넘는 노드는 건너뜀, script·style·noscript·template·title 제외. 8자리 이하 숫자열은 걸지 않는다.
- **shadow DOM·iframe**: 열린 shadow root 와 같은 출처 iframe 안까지 적용한다.
- **실패 화면 스크린샷**: 사이트 셀렉터·자동 감지·입력칸 기준으로 가린다(스텝 `mask` 없음).
- **가리지 못하는 것**(문서에 밝힌다): 영상은 화면 블러·점 표시만 담고 단색 상자·스텝 `mask` 는 담지 않는다. 블러는 개인정보 제거를 보장하지 않는다 — 첫 페인트 전·디바운스 동안 몇 프레임 보일 수 있다. 개인정보가 담길 수 있는 시나리오는 영상을 끄라고 안내한다. 캔버스·이미지 속 글자, 닫힌 shadow DOM, 다른 출처 iframe, 패턴에 맞지 않는 개인정보(이름·주소 등)는 가리지 못한다.
- **시각 회귀와의 관계**: 별도 "비교 제외 영역"은 두지 않는다. 같은 단색 상자라 사실상 비교에서 빠진다. 가격·시각 같은 바뀌는 영역은 스텝 `mask` 로 가리라고 안내한다.
- **설정 화면**: 사이트 설정에 셀렉터 목록(여러 줄, 저장 때 검증, 도움말), 시나리오 설정에 켜기/끄기. 권한은 사이트·시나리오 쓰기와 같다.

## 6. 환경 비교

- **시작 전 검사**(하나라도 걸리면 이유 목록과 함께 400): 두 환경이 서로 다르고 같은 사이트에 있으며 기본 주소가 다르다, 스크린샷 스텝이 1개 이상, 저장 세션을 쓰면 **요청자 본인**의 양쪽 환경 세션이 있다, 앱 실행이면 요청자의 앱이 연결돼 있고 필요한 기능(7절)이 있다. 시작 화면에 "두 환경에서 시나리오 전체가 각각 실행돼요. 주문·결제처럼 상태를 바꾸는 시나리오는 피하세요" 안내(막지는 않는다).
- **만들기**: 비교 1건과 자식 실행 2건(좌·우)을 한 트랜잭션으로. 실행 조건 사본과 해석된 기본 주소를 저장하고, 자식은 그 사본으로만 실행한다. 변수·세션은 요청자 기준으로 실행 때 해석한다(사본에 값 없음).
- **자식 실행**: 시각 회귀 비교·기준 생성, 세션 저장, 알림, 실행 전체 재시도를 끈다(시도가 하나라 화면이 섞이지 않는다). 스텝 재시도는 그대로. 스크린샷 스텝마다 이미지와 **접근성 스냅샷**(본문, iframe 제외)을 연달아 찍고, 렌더링 조건을 기록한다.
- **스냅샷 가림**(정규화·자르기 전에, 이 순서로): ① 이미지와 같은 가림 대상의 노드를 캡처 동안만 접근성 트리에서 숨기고, 그 요소를 이름·설명으로 참조하는 바깥 요소와 label 연결도 숨긴다(열린 shadow root 포함). 끝나면 원래대로 되돌린다(중간 실패에도). ② 입력 요소의 값은 싣지 않는다. ③ 그 실행의 비밀 값(세션 값 포함)으로 `maskSecrets`. ④ `redactText`(이메일·전화·URL 쿼리, 설정과 무관하게 항상). ①이 시간 예산을 넘기거나 숨길 수 없으면 **마스킹 실패** → 그 스텝 구조 비교는 `incomparable`, 원문을 저장하지 않는다.
- **확정**: 양쪽 자식이 모두 끝나면(실행 종료 지점마다 시도) 조건부 갱신으로 `running → comparing` + 새 `claimToken`·`claimExpiresAt`(2분). 결과 저장은 `status = comparing AND round = r AND claimToken = t` 일 때만 한 트랜잭션으로, 끝나면 `done`(또는 `error`). 점유가 만료된 `comparing` 은 worker 의 정리 작업이 같은 방식으로 다시 점유해 끝낸다(프로세스가 죽어도 남지 않는다).
- **원본 고르기**: 자식 실행은 시도가 하나이므로 스크린샷 스텝마다 그 실행의 그 스텝 ID 결과를 쓴다. 비교용 스크린샷은 촬영마다 고유 이름으로 저장한다.
- **다시 비교**: 양쪽 자식이 끝났고 비교가 `done`·`error` 일 때. `round` 를 올리고(점유 토큰도 새로) 이미 찍힌 화면으로 다시 판정한다. 허용 오차를 바꿀 수 있다. 취소된 비교는 다시 비교할 수 없다.
- **화면 판정**: 3절 엔진, 허용 오차는 비교마다(기본 5%, 0~100). 원본 없음·실패·크기 초과·캡처 시간 초과·마스킹 실패·렌더링 조건 불일치는 `incomparable`.
- **구조 판정**: 정규화(개행 형식·줄 끝 공백, 링크 `{origin}`) 뒤 같으면 `same`. 다르면 요소 단위 diff: 같은 요소(역할·이름·주요 속성이 같은 줄)를 짝지어 **순서 이동**, **한쪽에만**, **내용 변경**(같은 위치·역할에서 이름이나 값이 다름)을 센다. 순서만 바뀌어도 `different`.
- **제한**(초깃값, 실측으로 조정): 스냅샷 256KiB 또는 5,000줄, 캡처 3초, diff 계산 2초·편집 거리 2,000줄(넘으면 diff 없이 "다름"과 사유), 화면에 펼치는 diff 앞 400줄(넘으면 접기·"전체 보기").
- **전체 판정**(화면·구조 따로): 자식이 실패·취소됐거나 마스킹 실패가 하나라도 있으면 `incomparable`(차이가 있어도 — 조건이 온전하지 않은 비교로 "다름"을 단정하지 않는다, 스텝별 결과는 그대로 보인다). 아니면 하나라도 `different` 면 `different`, `incomparable` 스텝이 있으면 `incomparable`, 나머지 `same`.
- **목록·상세**: 목록은 최신순(기본 50, 최대 100), 필터는 판정·시나리오 이름·사이트·실행 위치·날짜. 상세는 스텝마다 좌 | 우 | diff(확대), 구조 diff(이동·한쪽에만·변경 표시, 긴 diff 접기), 판정·차이·SSIM·판정 설명, 적용한 가림, 양쪽 캡처 시각과 렌더링 조건, 자식 실행 상태. 진행 중에는 새로 고친다.
- **취소**: 비교가 `running` 일 때만. 한 트랜잭션에서 비교를 `cancelled` 로 바꾸고 양쪽 자식에 취소 요청을 기록한다(실제 중지는 기존 실행 취소 경로). `comparing` 이후에는 취소를 받지 않는다(짧다). 앱 실행 비교는 그 기기 주인만(403).
- **파일 쓰기**: diff·구조 diff 는 확정 점유를 가진 작업만 쓴다(`EnvComparisonFile`). 실행 산출물 업로드 경로(실행 점유 필요)를 쓰지 않는다.
- **권한**: 읽기 `run.read`, 시작·다시 비교 `run.create`, 취소 `run.cancel`. 다른 워크스페이스 404. MCP 에는 열지 않는다.

## 7. 앱 기능·프로토콜 (`packages/shared` — 리드 선행)

- 앱 기능 이름 더함: `masking-v1`(5절 초기화 스크립트·캡처 직전 덮기·촬영 거부), `visual-compare-v1`(4절 기준 내려받기·판정 보고), `a11y-snapshot-v1`(6절 스냅샷 캡처와 가림).
- 서버가 앱에 실행을 배정할 때 필요한 기능: 모든 실행 `masking-v1`, 기준이 있는 스크린샷 스텝이 있으면 `visual-compare-v1`, 환경 비교 자식이면 `a11y-snapshot-v1`. 없으면 기존처럼 `409 app_update_required { missing }`(배정 전 거절, 거짓 통과 방지).
- 실행 메시지에 더함: 기준 고정 목록(버전 ID·키·크기·렌더링 조건), 마스킹 설정(셀렉터·켜기·정책 버전), 비교 자식 표시. 스텝 결과에 더함: 시각 판정·원값·기준 버전 ID·렌더링 조건, 스냅샷 산출물 키. 스키마는 엄격 그대로 두고 칸을 더한다(구버전 앱은 위 기능 검사로 배정 전에 걸러진다).

## 8. 시험

- 엔진: 크기 다름, 크기 0, 허용치 경계(같으면 일치), 원값 판정(0.004% 차이가 허용치 0 에서 다름), SSIM 경계, 허용 오차 0 엄격, diff 생성 규칙(시각 회귀·환경 비교 각각).
- 시각 회귀: 기준 없음 → 생성, 일치, 변경 → 경고(실행 통과), 승인 → 다음 실행 일치, 실행 중 승인 → 그 실행 경고 유지, **동시 첫 기준**(한쪽만 `created`, 다른 쪽은 비교 판정), **동시 승인**(한쪽 409), 다시 승인(같은 결과), 다른 기기·실행 환경·환경 → 다른 기준, 렌더링 조건 다름 → `incomparable`, 스텝 삽입 뒤에도 기준 유지, 실행 정리 뒤에도 기준·과거 결과의 기준 버전 유지, **고아 정리가 기준 사본을 지우지 않음**, 승인 권한(보기 전용 403, 다른 워크스페이스 404), 앱 실행 경로, **기준 내려받기 인증**(다른 기기·끝난 실행·고정 목록 밖 버전 거절), 앱 판정의 버전 위조 → `skipped`.
- 마스킹: 사이트 셀렉터·자동 감지·스텝 `mask`·입력칸이 스크린샷에서 가려짐(픽셀 확인), 늦게 나타나는 요소, 입력값 변경, 계속 바뀌는 페이지에서 최대 지연, 입력 직전 강제, 시나리오 끄기(입력칸·스텝 mask 는 유지), shadow DOM·같은 출처 iframe·팝업, **저장 때 잘못된 셀렉터 거부**, **가림 실패 → 찍지 않음**, 마스킹 켜진 실행에 trace 없음, 첫 페인트·팝업의 영상 프레임(실기).
- 환경 비교: 시작 전 검사 각 이유, 구버전 앱 거절, 자식 격리(목록·알림·정리 제외), 확정 경합(한 번만), **확정 중 프로세스 종료 → 점유 만료 후 재점유로 완료**, 다시 비교·허용 오차 변경, **다시 비교·취소 경합**(낡은 점유는 쓰지 못함), 스냅샷 가림·**비밀 값이 든 스냅샷**·실패 → `incomparable`, 요소 단위 diff(이동·한쪽에만·변경), 링크 정규화, 제한 초과, 한쪽 실패 → 전체 `incomparable`, 취소, 권한.
- 실기(리드, 마지막): 이 Mac 의 앱으로 시각 회귀 승인 한 번, 두 환경 비교 한 번, 영상 프레임 확인.

## 9. 진행 순서와 담당 경계

1. **리드 선행**: 2절 마이그레이션, 고아 정리 확장, 7절 기능 이름·프로토콜 칸·판정 enum·셀렉터 파서와 검증, 3절 비교 엔진(시험 포함), 렌더링 조건 수집 함수.

3. 병합 → 전체 시험 → Docker 빌드 → Codex 구현 검토 → 수정 → 실기 → push(사용자에게 묻고).
